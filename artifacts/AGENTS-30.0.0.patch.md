# AGENTS.md 30.0.0 补丁说明

本次目标版本：`29.1.0 -> 30.0.0`。变更重塑默认 Skill 门禁与多 Agent 工作模型，属于不向后兼容的治理行为变化，因此升级 `MAJOR`。

## 变更原因

`29.1.0` 对每个文件修改都加载完整治理 Skill，并在收益门禁通过后要求主动派遣。该组合会让普通 L1/L2 工作承担无关上下文、路由判断和协调成本，也会与运行时更高优先级的派遣限制发生摩擦。

## 修改内容

1. `seer-codex-rules` 改为治理敏感条件路由；普通 L1/L2 与单文件修改不再触发通用 compliance gate，匹配的其他 Skills 仍正常加载。
2. 全局纲要压缩为通用行为、授权边界、规则位置、L0-L4、治理触发、最小验证和净收益多 Agent 边界；详细流程继续按需进入 references。
3. 多 Agent 从“门禁通过即派遣”改为“有界、独立、互斥、运行时允许且净收益明确时才派遣”；容量只是上限，根任务继续负责范围、写入所有权、集成和最终验证。
4. 固定模型、固定推理档位、31/32 容量及 `features.multi_agent_v2` 不再作为治理事实；V2 仅作为非公开、不可移植兼容输入报告。
5. 临时 `AGENTS.override.md` 可在有明确作用域和恢复责任时使用，不要求用户逐字点名该文件。
6. 默认零哈希边界保持不变；只有实际 global/live 同步或恢复消费者需要字节一致性时，才在最终阶段比较一次。
7. `seer-codex-rules/SKILL.md` 成为精简路由器，详细治理与校验只按当前触发面加载。

## 相关 Seer Skill 变更

独立分发仓库仅修改 `seer-capture`、`seer-project-space-health`、`seer-math-exam`、`seer-mathbook` 和 `seer-prepare-open-source-release` 的触发或渐进披露边界。全部 `nature-*` 源码、版本、测试、安装副本及 `.agents` 重复副本冻结，不属于本次发布。

## 状态边界

- `docs/HANDOFF.md` 不随实现、验收、安装或发布刷新；只有以后再次明确请求交接时才整体重建。
- 不重复已完成的 31 子 Agent 压测。
- 源仓库、分发仓库、维护环境安装和 GitHub Release 分别记录证据；在验收完成前不声称已安装或发布。
- 当前检出树只保留最新版本化 artifact/release 资产；Git/GitHub 历史不改写。
