# AGENTS.md 27.13.0 正式发布补丁说明

本次版本动作：`27.12.0 -> 27.13.0`，按最高影响属于 `MINOR`。全局规则、项目 `VERSION`、Git tag 和 GitHub Release 统一使用 `v27.13.0`。

## 变更原因

GPT-5.6 在持久、主动的 Agent 工作中会放大重复或分散的“确认、验证、安全、验收”措辞。现有规则虽然已有停止条件，但授权边界、验证选择、重试预算和 Goal 优先级散落在多个模块，容易被解释为叠加清单。

## 修改内容

1. 将只读请求与修改请求的授权边界集中到全局核心原则；目标内本地编辑和非破坏性验证无需再次确认。
2. 同一动作类别、目标和风险等级形成一个授权范围，只有真实边界变化或运行时要求时才重新确认。
3. 建立 V0 直接、V1 行为、V2 affected、V3 full 验证梯；低层证据足够时禁止机械升级。
4. 为全量回归、完整构建、端到端和安全扫描定义真实变更面触发器。
5. 缓存通过证据；只有覆盖的代码、测试、配置、依赖、生成输入或环境变化才失效。
6. 区分本轮失败、既有失败、瞬时失败、外部阻塞和未知失败，限制修复与重试范围。
7. Goal 模式成为持续任务唯一循环预算，普通验收只负责边界分类，不再叠加第二套预算。
8. 开始读取一次 Skill，结束复用已加载规则；严格 guardrail 和全量测试保留给同步、共享基础设施或发布。

## 研究依据

- OpenAI GPT-5.6 指南建议精简系统提示、每条规则只写一次，并明确指出重复的确认措辞会导致安全动作也频繁请求授权。
- Codex、Claude Code 和 OpenHands 都将安全执行交给 sandbox、permission 或风险阈值，而不是要求模型对每个普通动作重复口头审计。
- OpenAI Agents SDK、AutoGen 和 LangGraph 都提供显式轮次、消息、token、超时或递归终止条件。
- Agentless 证明简单的定位、修复、验证流程可以兼顾效果与成本；2026-07 的验证研究进一步表明，通过的测试不一定对原始缺陷有区分力。

## 验证要求

- 正式 artifact、live 全局和 Downloads 副本保持字节一致。
- Skill 三份源码保持一致，新增效率锚点通过 guardrail。
- 只运行受影响的 guardrail 单元测试、Skill validator、measure、严格同步校验和 diff 检查；不因本次规则改动执行无关多 Agent 路由或结构热点测试。
