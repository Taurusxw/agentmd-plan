# AGENTS.md 29.0.0 正式补丁说明

本次正式版本动作：`28.1.0 -> 29.0.0`，按最高影响属于 `MAJOR`。全局规则、项目 `VERSION`、Git tag、GitHub Release、release 目录和公开 artifact 统一使用 `29.0.0`。

## 变更原因

旧规则把单 Agent 设为默认并以 1/2/3 固定数量控制协作，导致适用 Skill 已明确要求并行时仍可能被 `ExplicitRequestOnly` 误判为未授权；同时旧配置校验混淆 V1 子线程数与 V2 总槽位，并把 Terra/high、Terra/max 固化为所有工作的最低成本。需要在不依赖 Ultra、隐藏开关或平台绕过的前提下，建立 Agent-first、自适应容量、多模型分工和可量化 token 经济性。

## 修改内容

1. 全局规则明确授权：收益门禁通过时，主 Agent 必须主动派生合适子 Agent，无需用户再次点名或使用 Ultra。
2. 删除 1/2/3 固定治理上限；每一波数量取就绪独立工作包、实时空闲槽位和任务/时间/token 预算的最小值，容量不是利用率目标。
3. 采用根编排、发现波、汇总屏障、互斥写入波和风险复核波；禁止重复工作与同文件并行写入。
4. 区分 V1 子线程容量和 V2 含根总槽位；当前可移植模板显式启用 V2，总容量设为 32，并要求新任务探测实际生效值。
5. 路由改为能力阶梯：Terra/medium 默认与探索，Terra/high 实现，Sol/high 重大风险复核；仅按包复杂度升级到 low/high/max 等合适档位，Ultra 不再作为派遣前提。
6. 异构角色默认使用 `fork_turns="none"` 和紧凑上下文；只在连续性收益明确时携带有限或完整历史。
7. 默认采用根节点平铺编排；只有父任务包明确授权递归子树时才允许嵌套，并继承同一收益、所有权、容量与结果压缩门禁。
8. `agent_routing_check.py` 改为后端感知、允许高正整数容量、拒绝 V1/V2 冲突并验证能力类别；guardrail 与测试增加显式授权、自适应 fan-out 和 fork 语义锚点。

## 版本依据

本次从“单 Agent 默认 + 固定并发上限”切换为“满足门禁即主动派遣 + 自适应波次”，并改变容量语义、模型路由和兼容方式，属于全局工作模型变化，因此升级 `MAJOR` 到 `29.0.0`。

## 状态边界

- 解析器接受高容量或提示显示 32 个槽位，不等于账号或后端保证真实同时运行 32 个 Agent；运行时硬限制始终优先。
- 多 Agent 通常以更多总 token 换取时间、覆盖或质量，不承诺绝对省 token；通过便宜模型、fresh context、紧凑输出、去重和分波停止规则优化单位有效结果成本。
- 当前检出树仅保留最新发布资产，并在发布后清理本地旧 tags；GitHub 的旧 tags/Releases 与 Git commit 历史均保留。
- 回退依赖 Git commit 历史或使用者自己的本地备份；不得用 reset/checkout 覆盖未提交工作。
